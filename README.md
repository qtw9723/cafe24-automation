# Cafe24 백오피스 일일 모니터링 자동화

Cafe24 챗봇 연동 상점들을 관리하는 사내 백오피스에서 매일 손으로 하던 점검 루틴을
Selenium으로 자동화하고, 결과를 HTML 메일로 받아 보는 개인 프로젝트입니다.
2026년 5월부터 매일 크론으로 무인 운영하고 있습니다.

## 왜 만들었나

매일 아침 백오피스에 들어가 로그 수집 → 합계 확인 → 대시보드 수치 대조 → 어제와 에러 비교 →
메모 작성 → 8개 체크리스트 체크를 반복해야 했습니다. 단계는 단순한데 빠뜨리기 쉽고,
에러가 늘었을 때는 바로 알아야 했습니다. 이 루틴을 그대로 스크립트로 옮기고, 이상이 있을 때만
사람이 보도록 메일 알림을 붙였습니다.

## 하는 일

| 단계 | 화면 | 내용 |
|---|---|---|
| 1 | Shop | 전체 상점 선택 후 오늘·이번 달 로그 수집 실행 |
| 2 | log stats | 오늘 로그 합계와 이번 달 에러 합계 집계 |
| 3 | Dashboard | 대시보드 수치와 2단계 합계 교차 검증 |
| 4 | daily check | 어제 메모의 에러 건수와 비교, 증가하면 중단 후 경고 메일 / 아니면 오늘 메모 작성·저장 |
| 5 | daily check | 점검 체크리스트 8개 항목 체크 후 저장 |

부가 기능:

- **도메인 해지 감지**: 실행 전에 별도 프로브(백오피스 저장소의 `tools/cancel_probe`)가 상점별 API를
  조회 전용으로 한 번씩 호출해 해지(401) 신호를 누적하고, 결과를 성공 메일에 덧붙입니다.
- **결과 메일 4종**: 성공(실제 수치 요약), 실패(로그를 파싱한 단계 진행·핵심 에러), 서버 다운, 에러 증가.

## 구조

```
cafe24_automation/
├── main.py                 # 진입점: 서버 도달성 확인 → 드라이버 기동 → 1~5단계 → 결과 메일
├── config.py               # 셀렉터·대기시간·재시도 설정, .env 로딩
├── run_daily.sh            # 크론 래퍼: 중복 실행 락, .env 로드, 해지 프로브, caffeinate, 종료코드별 처리
├── steps/                  # 단계별 Selenium 시나리오 (step1 ~ step5)
├── utils/
│   ├── email_notifier.py   # Gmail SMTP 발송 + 메일 종류별 본문
│   ├── email_html.py       # 다크 테마 HTML 메일 렌더러 (인라인 스타일 + table 레이아웃)
│   ├── send_failure_mail.py# 크론 실패 시 실행 로그를 파싱해 HTML 실패 메일 생성
│   ├── logger.py / parser.py / wait.py
├── dev/                    # 셀렉터 디버깅·단계별 단독 테스트 스크립트
└── docs/
    ├── history/            # 초기 수정 기록 (당시 문서 그대로 보존)
    └── launchd/            # launchd 방식 plist 예시 (현재는 cron 사용)
```

## 실행

```bash
pip install -r requirements.txt
cp .env.example .env        # 백오피스 주소, Gmail 앱 비밀번호, 수신자 입력
python3 main.py             # 수동 1회 실행
```

크론 등록 (매일 11:00):

```
0 11 * * * /path/to/cafe24_automation/run_daily.sh
```

결과는 `output/`에 남습니다. `cron_schedule.log`에 실행마다 성공/실패 한 줄,
`cron_run_<시각>.log`에 전체 로그가 쌓입니다.

종료 코드: `0` 성공 · `1` 단계 실패(실패 메일 발송) · `2` 백오피스 서버 응답 없음(서버 다운 메일은 main.py가 이미 보냄).

## 운영하면서 고친 것들

실제로 매일 돌리면서 부딪힌 문제와 해결입니다.

- **예약 시각에 아예 안 돌던 문제**: 08:00 크론이 자주 건너뛰어졌습니다. `pmset` 로그를 보니
  예약 기상은 됐지만 노트북 덮개가 닫혀 있으면 약 10초 만에 `Clamshell Sleep`으로 다시 잠들었고,
  cron은 놓친 작업을 나중에 실행하지 않습니다. `caffeinate`나 `pmset sleep`은 덮개 닫힘 절전을
  막지 못한다는 것도 확인했습니다. 실행 시각을 자리에 있는 11:00으로 옮겨 해결했습니다.
  launchd(`StartCalendarInterval`)는 놓친 작업을 따라잡지만 무인 실행 시 Chrome 키체인 잠금 문제가 있어
  예시 파일로만 남겨 두었습니다.
- **회사 메일로 알림이 반송되던 문제**: macOS `mail`로 보내던 알림이 Office365에서 발신 IP 기준으로
  차단(550 5.7.1)됐습니다. 계정 인증 방식인 Gmail SMTP(587 STARTTLS)로 바꿨고, 서버가 250을 돌려줘야만
  성공으로 기록하도록 해서 "보냈다고 했는데 안 온" 경우가 없게 했습니다.
- **Outlook에서 메일이 깨지던 문제**: Outlook이 메일 배경을 회색으로 덮어써서 밝은 디자인이 읽히지 않았습니다.
  처음부터 다크 디자인으로 만들고, 스타일은 전부 인라인·table 레이아웃으로 바꿨습니다.
- **서버가 꺼져 있으면 오래 매달리던 문제**: Selenium을 띄우기 전에 TCP로 먼저 접속을 확인해,
  서버가 내려가 있으면 바로 종료 코드 2와 서버 다운 메일로 끝냅니다.
- **브라우저 세션이 가끔 죽는 문제**: `invalid session id` 같은 일시적 오류에 대비해 전체 실행을 최대 2회 재시도합니다.
- **거짓 성공 방지**: 일부 단계만 끝났는데 성공 메일이 가던 경우를 막으려고, 모든 단계가 성공했을 때만 종료 코드 0을 반환합니다.
- **에러 건수 기준값**: 대시보드 텍스트 스크래핑은 요소를 못 찾아 0이 나오는 일이 잦아서, log stats 표 합계를 기준값으로 씁니다.

## 기술 스택

Python 3.9, Selenium 4 + webdriver-manager, Gmail SMTP, bash + cron (macOS)
